# Exam 完整認證 V3 遷移與三前端共通核心實作計畫

## 1. 目標

將 Exam 的密碼登入、Email 登入、Token verify／refresh 與 logout 切到 V3，並讓 `authContract.ts`、`refreshCoordinator.ts`、`handleUser.ts`、`useAxios.ts` 與 Hand／Manage 完全相同。測驗、分析、統計與既有 Exam 設定不在本計畫修改。

## 2. 修改設計

- 新增與 Hand／Manage 相同的 `authContract.ts`，集中五個 V3 path、response guard與錯誤解析。
- 新增相同的純 `refreshCoordinator.ts`，由 local Node probe實際執行 refresh leader／waiter成功與失敗收斂。
- `handleUser.ts` 改 V3 login／logout與嚴格 Token 儲存；既有 signup adapter維持 V1。
- `useAxios.ts` 改 V3 refresh，保留其他 Exam API 的 `USER_API` base URL，補齊等待者 reject與單次逾期提示。
- `AuthContext.tsx` 使用 V3 verify、body `{}`、Bearer interceptor與共通 response guard。
- 兩個登入表單統一 V3 錯誤語意，不改測驗 UI。
- 新增 local contract probe 與 package script；保留現有 EmailCode V3 與 errorlog probes。

## 3. TDD 檢查點

### E0：基線與 RED

- 保存 branch/status/staged/unstaged/untracked；目前 `dev` ahead 4，且 `src/lib/config.ts`、`vite.config.ts` 已修改，兩者都受保護、不納入 allowed paths。
- Local probe 先對舊版認證 URL、弱 Token／verify body、refresh waiters failure hang呈 RED，並以既有 `typescript` 記憶體內轉譯執行純 Token guard／coordinator。

### E1：共通核心 GREEN

- 同步主代理已檢查的四個共通核心檔案；不得為 Exam 改 endpoint、Token key、error mapping或 queue。
- Root probe 必須證明四個共通核心檔案皆位元組一致，且 Exam dirty config未被觸碰。

### E2：Exam 外層接線

- 只替換 AuthContext verify與登入表單錯誤接線。
- 不修改 Analyze、Statistics、routes、Vite設定或測驗領域型別。

### E3：驗證與審查

從 `pigeon-exam/` 執行：

```text
pnpm test:auth-v3
pnpm test:email-code-v3
pnpm exec eslint src/auth/authContract.ts src/auth/refreshCoordinator.ts src/auth/handleUser.ts src/auth/AuthContext.tsx src/hooks/useAxios.ts src/features/User/Login/PasswordForm.tsx src/features/User/Login/EmailForm.tsx
pnpm exec tsc -b
pnpm build
```

再執行 root parity probe、`git diff --check`、staged guard與 allowed-path guard；比較 `src/lib/config.ts`、`vite.config.ts` 前後基線，確保沒有本工作新增 hunk。

## 4. 驗收條件

- AC-E-1：五個認證操作只使用 V3；signup 相容 adapter為唯一 V1 例外。
- AC-E-2：四個共通核心檔案與 Hand／Manage 位元組一致。
- AC-E-3：verify Bearer＋`{}`、Token／verify response嚴格，弱成功 fail closed。
- AC-E-4：refresh 成功／失敗完整 settle所有等待者，零永久 pending與重複 dispatch。
- AC-E-5：登入錯誤與 Hand／Manage 同語意；unknown／timeout零重送。
- AC-E-6：既有 config／Vite dirty hunk、EmailCode、Analyze與測驗流程不退化。
- AC-E-7：無 UI 重設計、無新 dependency、無其他 API 遷移。
- AC-E-8：probe、lint、typecheck、build及未執行 gate如實記錄。

## 5. 停止條件

Producer 漂移；需要改 `src/lib/config.ts`／`vite.config.ts` 或測驗流程；共通核心需 Exam 專屬依賴；dirty hunk 無法歸因；同檔修正三輪不收斂。
